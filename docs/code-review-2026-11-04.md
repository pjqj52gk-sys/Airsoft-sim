対象: 現行エディター、画像処理、検索・カタログ照合、商品取り込みAPI、共有カスタム、保存・比較、旧エディターの静的検査。各メーカー全商品のデータ監査や本番負荷試験は含めない。

| P2 | 商品ページの関連商品リンクから別サイズを寸法候補として抽出 | 寸法・識別情報の走査では別ページへのリンク内容を除外。同一ページの仕様アンカーは保持 |

## 検証

- 全119テスト成功。保存の競合、失敗後の継続、画像の最大同時処理数、順序保持、関連商品の寸法混入に回帰テストを追加。
- TypeScript型検査と本番用ビルド成功。
- 変更した現行コードのeslintエラー0件。全体の既存エラーは22件から14件へ減少。残る14件はapp/legacy内。画像タグ等の既存警告は35件。
- ブラウザー: 3段のダイアログをEscで1段ずつ閉じても、背面の検索画面が残ることを確認。
- ブラウザー: 本体検索は447件中48件を表示し、追加操作で96件。HK416検索は本体5件。数値入力800→805→Undoで800に戻ることを確認。
- 実商品: military-base/h9523b155の取り込みで、関連商品由来の35/30/25mmが消え、155mm・40mmだけ残ることを確認。1320×990px画像の取得も確認。
- 共有データベースへの投稿・公開状態の変更、本番の負荷試験は実施していない。

## 残る改善点

1. 旧エディターは既存の型・Hook・const等のlintエラー14件が残る。現行画面へ機能を移すか、旧画面を引き続き保守するかの整理が必要。
2. 商品寸法の抽出は引き続きヒューリスティック。リンクではない関連商品表示やメーカー独自の表構造まで、今回の修正だけで完全には判別できない。カタログにもLVOA系の75mm等、再確認すべき候補が見られる。元ページと抽出根拠を照合するデータ監査を次に行うとよい。
3. studio.tsxに履歴・保存・追加・編集・画面制御が集中している。今後はワークスペース状態と画像追加処理を専用Hookに分けると変更の影響を追いやすい。今回は保存形式と画面構成を保ち、問題のある処理を限定して修正した。
4. 共有一覧のいいね数は都度集計している。投稿・評価が増えた時点で実行計画を測定してから集計方法を選ぶ。今回は本番データの変更を伴う構造変更を行っていない。
